**结论：** 好规范 = **具体不模糊 + 有优先级不贪多 + 带原因**。第一版只覆盖 AI 最容易跑偏的四处；规范分全局 / 模块 / 任务三层，任务可覆盖模块，但不可违反全局。

---

## 三条标准

### 1. 具体，不模糊

判断标准很简单：**AI 看到这条规范后，是否还需要「猜」你的意思？需要猜就不够具体。**

| 没用 | 有用 |
| --- | --- |
| 代码要简洁 | 不引入不必要的设计模式（工厂 / 策略 / 观察者），除非明确要求；每个功能用最简单直接的方式实现 |
| 接口要规范 | 所有接口统一返回 `Result<T>`（code / message / data）；错误码四位数字按模块分段 |

「简洁」AI 的理解和你不一样——它可能觉得一个工厂模式 + 策略接口就是简洁的抽象。

### 2. 有优先级，不贪多

**AI 反复跑偏的地方写细，不跑偏的地方不写。** 上下文窗口有限，塞太多规范反而稀释重要的那几条。

- 「文件编码用 UTF-8」——AI 基本不会错，不值得占篇幅
- 「Controller 不写业务逻辑」——它经常犯，必须写

Hify 的 CLAUDE.md 最终大概两三页，每一条都是因为 AI 在那个点上跑偏过才补的；没跑偏过的地方，一条都没有。

### 3. 带原因，不只是规则（真实 A/B 案例）

第 15 讲做 Agent 工具列表更新时，指令写了「不要全量删除再全量插入」——**AI 第一版还是全量删除再插入，它不理解为什么不能这样。**

补一句解释：「全量删除再插入会导致并发场景下 Agent 瞬间失去所有工具关联，如果此时有对话正在读取工具列表，会拿到空列表。」**第二版它就用了差异比对的方式。**

涉及工程权衡的规范，加上「为什么」，AI 的遵循度明显更高——它能在没覆盖的边界情况里按原因举一反三，此时它会跟你讨论，可能你想的还不对。边界：「实体类不加前缀」不需要解释，照做就行。

## 第一版覆盖四处（最容易跑偏）

```text
# 命名规范
实体类大驼峰不加前缀后缀（Provider、Agent、ChatMessage）；字段小驼峰（apiKey、baseUrl）
接口路径 /api/v1/{资源复数名}

# 接口规范
统一返回 Result<T>：{ code, message, data }
列表空时返回 []，不返回 null；分页 page（从 1 开始）、pageSize（默认 20）

# 错误码（四位数字按模块分段）
1000-1999 通用 | 2000-2999 Provider | 3000-3999 Agent | 4000-4999 Chat | 5000-5999 MCP

# 设计原则
不引入不必要的设计模式；不做过度抽象（一层能解决不拆两层）；不引入技术栈以外的依赖（需要先确认）
```

> 四块加在一起一页纸。但有和没有之间的差距，就是完成和完美之间的差距。
> 技巧：先让 AI 帮你梳理「这个项目需要定哪些规范」，它帮你想，你来判断取舍。

## 三层分工（叠加生效）

| 层 | 载体 | 内容 | 变更频率 |
| --- | --- | --- | --- |
| 全局 | 根 `CLAUDE.md` | 命名 / 接口格式 / 错误码体系 / 设计原则 / 行为约束 | 初期定好，很少改（**地基**） |
| 模块 | 模块目录下 / 开发前指令 | 某模块的接口契约、数据流定义、节点类型规范 | 每模块开发前写那个模块 |
| 任务 | 下达任务时补充 | 「这次不需要分页」「用差异比对不要全量替换」 | 临时性，**不落文档** |

优先级从上到下：任务规范可覆盖模块规范（这次不分页），但不可违反全局规范（统一 `Result<T>`）。子目录 CLAUDE.md 叠加在根之上生效；五层骨架与行为指令见 [07 模板](/ai/sdd/07-templates/)。

## CLAUDE.md 塞太多的症状（自检清单）

- 文件超过 **200~300 行**
- 里面有大量「步骤 1/2/3」的操作流程
- 不同模块的规范混在一起
- AI 开始忽略靠后的内容

正确分拆：先问「**这句话是全局规范还是任务流程**」。「用 AssertJ 做断言」是全局规范 → CLAUDE.md；「单测的完整流程是先读代码、输出路径分析、给测试计划、确认后写代码」是任务流程 → Skills。

## 改系统时：需求文档六维

老项目改造里，「规格」先以需求文档落地，六维缺一不可：

> 业务目标 · 用户场景 · 接口契约 · 边界场景 · 老项目约束 · **不做的事**

「不做的事」最容易被漏，却最值钱——它圈死范围：「『对比两个版本』扩展开可能变成『对比 N 版本』『对比附评分』『导出 diff』，不写『不做这些』，AI 就会顺手给你做了」。完整六维模板与 AI 能力地图见 [07](/ai/sdd/07-templates/)。

## 产品边界：三问裁剪法

定「做什么 / 不做什么」时，对每个候选功能问三句：

1. 没有它，产品还成立吗？（核心 / 边缘）
2. 做到什么程度够用？
3. 能不能一句话说清？

AI 做初筛（分「必须做 / 降级 / 砍掉」三档），你拍板。
