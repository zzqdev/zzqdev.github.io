**一句话：** SDD 把「先想清楚再写代码」落成可执行工件——规范是合同，实现与测试都对着它走，代码变成规格的「编译产物」。写 Prompt 是一次性技巧，SDD 是贯穿项目的方法论。

人负责定边界、定标准、做取舍、验收；Agent 负责按规格落地。改需求先改规格，再改代码。

> 译名：Robert 全链路课译「**规范**驱动开发」，实战营译「**规约 / 规格**」，本系列统称 SDD，三者同义。

## 材料边界

- 主线：Robert《企业级全链路开发实战》02 讲（SDD 核心方法论）、31 讲（SDD/Spec-Kit/Spec Coding 进阶）；《企业级老项目改造实战》需求文档与验收诸讲
- 辅证：《企业级 AI 编程实战营》认知篇「SDD 与 Harness 两大支柱」、扩展篇「Spec-Kit / OpenSpec 教程」、项目篇 OryxOS（Spec-Kit 真实落地）与 When（轻量手工模式 + 任务卡片）的真实工件
- 不做：把某一支工具的命令当方法论本身；命令随版本会变，闭环与判断标准不变。资料内部矛盾处已在 [09](/ai/sdd/09-pitfalls/#资料存疑处写博客落地前请核实) 标注

## 和本站其他栏目的关系

- [老项目理解](/ai/legacy-project/)：摸清存量是改系统的前置；SDD 是增量交付时的「先规格」，两者在「需求文档 + 验收」处合流（老项目刻意不走重型 SDD，见 [09](/ai/sdd/09-pitfalls/)）
