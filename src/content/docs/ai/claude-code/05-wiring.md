文档写「Claude chooses / decides」时，多半指 **模型层**。  
它读 Context、决定下一步——但**从不直接**碰文件系统或网络：只发结构化 tool call。

Harness 负责解析、鉴权、执行、回灌。这是安全边界，也是「产品 ≠ 模型」的技术含义。

材料：[How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works)、[Glossary](https://code.claude.com/docs/en/glossary)。

![模型层、可及面与环境三分](/ai/claude-code/05-model-access.svg)

## 1. 模型层：谁在推理

职责很窄：

- 读当前 Context  
- 决定下一步：继续问、调哪个工具、还是给出最终说明  
- 输出文本块和/或 tool_use 块  

模型可换（Sonnet / Opus…；`/model` 或 `claude --model`）；**Harness 仍在**。

和扩展的关系：

| 扩展 | 谁决定用不用 |
| --- | --- |
| Skills / MCP / Subagent | 多半 **模型在环里决定**（或你显式 `/`） |
| Hooks | **事件驱动**，不经模型「想起来」 |
| CLAUDE.md | 启动已在 Context，模型每次都能看见 |

---

## 2. 可及面：能碰什么

Tools（含 MCP、代码智能）**实际作用的对象**：

| 可及面 | 例子 |
| --- | --- |
| 项目 / Git | 读写树、看 diff、提交（若放行） |
| Shell / 终端 | 构建、测试、脚本 |
| 外部服务 | 经 MCP 或 HTTP 类工具 |
| 浏览器等 | 自动化或只读拉取 |
| LSP / 诊断 | 代码智能插件提供时 |

在目录里启动后，默认可及项目树、终端能力、git 状态、CLAUDE.md、memory、已接扩展——相对「只看见当前打开文件」的补全，这是**仓库级**可及。

**可及 ≠ 已放行**：还要过 Gate（权限模式、规则、sandbox、trust）。

---

## 3. 「环境」为什么要三分

口语最容易把三件事揉成「环境」：

| 说法 | 真正在问 | 图上层 |
| --- | --- | --- |
| 「我在 IDE 里用」 | 壳 | **接入层** |
| 「跑本地还是云」 | 工具进程在哪 | **执行落点** |
| 「它能改我仓库吗」 | 作用对象 + 是否放行 | **可及面 + Gate** |

Remote Control 是经典陷阱：界面在远端，**执行与文件仍可在本地**——那是执行落点叙事，不是「换成了云可及面」。

拆开之后，排障才有方向：是壳的问题、跑在哪的问题，还是权限 / 可及面的问题。

## 4. 常见错配

| 错配 | 症状 | 更准的修法 |
| --- | --- | --- |
| 约定只写在聊天里 | 换 Session 就忘 | CLAUDE.md / rules |
| 用 Skill 代替 Hook | 「每次都要格式化」却经常忘 | PostToolUse Hook |
| 用 CLAUDE.md 代替 MCP | 「知道」API，却调不到真数据 | 接 MCP |
| 主会话里硬搜整库 | Context 爆 | Subagent 隔离 |
| 只改接入层客户端 | 换 IDE 仍重复踩坑 | 改输入约定与 Gate，而不是换皮 |

一句话：**模型 / 可及面负责「想」和「碰」；约束在输入层 / Gate；可复用知识在 Skill；强制动作在 Hook；外部能力在 MCP。**

---

## 5. 五个容易混的点

1. **模型 vs Harness** — 推理 vs 执行与门控  
2. **可及 vs 放行** — 看得见仓库 ≠ 已允许改 / 跑  
3. **接入 vs 执行落点** — 从哪说话 vs 跑在哪  
4. **模型决定 vs Hooks** — 环里选择 vs 事件必跑  
5. **换模型 vs 换产品** — 推理引擎可换，环还在  

能说明「模型不直接碰盘」+ 现场拆开接入 / 执行落点 / 可及面，这一篇就算过关。
