## 架构图：坑与验收

| 坑 | 你怎么拦 |
| --- | --- |
| 堆成一团 | 强调分层 |
| 前端缩成可怜小框 | 要求展开 UI ↔ API |
| 漏可观测链路 | 用手册「迭代补丁」补 OTel/监控 |
| 一次不满意 | 放大某层、数据库加表名，迭代 |

**验收：** 前后端边界对；核心模块有职责句；周边不抢戏。

---

## 模块依赖图：坑与验收

非 Java：手册里把 `pom.xml` 换成对应模块清单即可。

| 坑 | 你怎么拦 |
| --- | --- |
| 漏 start/main | 核对入口模块是否在图上 |
| 箭头画反 | 对照构建文件重画 |
| 前端混进模块图 | HTTP 调用的前端工程通常去掉 |
| transitive 爆炸 | 只画自己的模块 |

**验收：** 方向与构建文件一致；循环已标红或确认无。

---

## 外部依赖图：取证与验收

三类取证：

1. **框架/库** → 构建文件（只留主干）  
2. **中间件** → `application*.yml` / compose  
3. **外部 API** → README「配 Key」等  

缺中间件时用手册「补中间件」那句。

**验收：** 三类齐全；主干库而非全家桶；外部 API 与 README 对得上。
