## 1. 一句话与为什么存在

**RAG = Retrieval-Augmented Generation（检索增强生成）**  
生成前先从外部知识库取相关片段，再交给 LLM 回答。

解决 LLM 四短板：领域知识不足 · 信息过时 · 幻觉 · 私有数据安全。  
不把整库塞进上下文：token 贵，且**少量高相关上下文**通常比大段噪声更好。

## 2. 端到端链路（先背熟）

```
文档 → 解析/清洗 → 切片(Chunk) → 向量化(Embedding) → 向量库
                                                      ↑
用户问题(Query) → [检索前优化] → 检索(向量/关键词/混合) → [检索后:重排/压缩]
                                                      ↓
                              Prompt(问题+上下文) → LLM → 答案(+溯源)
                                                      ↓
                              评测(Ragas/人工/👍👎) → 只改指标指向的那一段
```

| 阶段 | 英文 | 干什么 |
|------|------|--------|
| 索引 | Indexing | 文档变可检索知识 |
| 检索 | Retrieval | 找到相关 Chunk |
| 生成 | Generation | 基于上下文作答 |
| 评测 | Evaluation | 定位该改哪一段 |
| （进阶）Agent | Agentic | 规划/工具/多步，不止问答 |

## 3. 范式演进（只记定位）

| 范式 | 是什么 | 今天态度 |
|------|--------|----------|
| **Naive RAG** | 切块→嵌入→相似度→拼 Prompt | MVP 必做 |
| **Advanced RAG** | 检索前/中/后系统优化 | 主战场 |
| **Modular RAG** | 模块可编排、非固定链式 | 复杂流程用 |
| **Agentic RAG** | 检索+规划+工具+反思闭环 | 多跳/要执行时再上 |
| **Graph / KG-RAG** | 实体关系图增强检索 | 成本高，Advanced 榨干后再考虑 |
| **Multimodal RAG** | 图文等跨模态 | 先 OCR+文本；再试点多模态向量 |

**选型共识**：多数场景 RAG 优先；微调适合固定口吻/通识；长上下文与 RAG **互补**不是替代。

## 4. 术语速查（能用自己的话解释即可）

### 4.1 索引侧

| 术语 | 一句话 |
|------|--------|
| **Chunk / 切片** | 文档切成的检索单元；太大噪声多，太碎丢上下文 |
| **Overlap / 重叠** | 相邻块重复一段，减轻切在句子中间丢信息 |
| **语义切片** | 按语义边界切，而非固定字数硬切 |
| **动态重叠切片** | 按内容调整重叠，提高覆盖 |
| **元数据 Metadata** | 块上的标签：来源、章节、时间、模块…用于过滤 |
| **Embedding / 嵌入** | 文本→向量，语义近则向量近 |
| **向量库 Vector DB** | 存向量并做近邻检索（如 Pgvector / Milvus / FAISS） |
| **ANN** | 近似最近邻，速度换一点精度 |
| **HNSW** | 常见 ANN 索引结构 |
| **量化（如 SQ8）** | 压缩向量，省内存/加速，略损精度 |
| **OCR** | 图/扫描件转文字；常需 LLM 纠错 |
| **版面分析** | 识别标题/栏/表/图区域，保证阅读顺序 |

### 4.2 检索侧

| 术语 | 一句话 |
|------|--------|
| **Query** | 用户原问题（或改写后的检索问句） |
| **相似度检索** | 用向量距离找近邻 Chunk |
| **Top-K** | 取最相似的 K 条 |
| **BM25** | 关键词稀疏检索，擅精确词、专有名词 |
| **混合检索 Hybrid** | 向量 + 关键词等融合，兼顾语义与字面 |
| **多路召回** | 多策略各取一批再合并 |
| **Rerank / 重排序** | 召回后再精排（专用 reranker 或 LLM 打分） |
| **Query 重写** | 把糊问题改成更清晰的检索句 |
| **Query 扩展** | 生成多角度问句，扩大召回面 |
| **HyDE** | 先让 LLM 写「假想答案文档」，再对该文档做向量检索 |
| **自查询 Self-Query** | 从问题里抽元数据条件（时间/标签），精确过滤 |
| **子查询分解** | 复杂问题拆成多个简单检索再汇总 |
| **精确检索 vs 模糊检索** | 有模块/ID/元数据约束 vs 纯语义相似；**尽量把模糊变精确** |

### 4.3 生成与质量

| 术语 | 一句话 |
|------|--------|
| **Prompt / 提示词** | 问题+规则+检索上下文，喂给 LLM |
| **上下文融合** | 如何组织多段检索结果进 Prompt |
| **提示压缩** | 丢掉无关段落，只留与问题相关的 |
| **幻觉 Hallucination** | 看似合理但无依据/错误的生成 |
| **溯源 / Citation** | 答案对应到原文片段，可核对 |
| **事实验证链** | 生成后再核对是否被上下文支撑 |
| **Faithfulness** | 答案是否忠实于给定上下文 |

### 4.4 微调与工程（知其何时用）

| 术语 | 一句话 | 何时想 |
|------|--------|--------|
| **Fine-tuning** | 继续训练模型吃领域风格/知识 | 口吻、固定技能；知识常变仍靠 RAG |
| **LoRA / Adapter** | 低成本参数高效微调 | 资源紧又要垂直适配 |
| **多模型路由** | 按问题选不同生成模型 | 成本/质量折中 |
| **冷热模型** | 高频用强模型，其余用轻量 | 降本 |
| **vLLM / 量化推理** | 加速推理、降显存 | 自建模型慢/贵 |
| **LangSmith 等** | 调用链追踪 + 回归测试 | 黑盒变可观测 |
| **MCP** | 模型连外部工具/数据的协议化「神经末梢」 | Agent 接工具 |
| **HITL** | 关键步骤人确认 | 高风险动作 |
| **Text2SQL** | 自然语言→SQL | 结构化库问答 |

## 5. 评测清单（先定指标再优化）

### 5.1 原则

1. **业务目标 → 指标 → 改技术**（改完再量指标）  
2. **指标指向哪一段，就只动哪一段**  
3. 没有黄金集时：先上 **用户 👍/👎**，再补标注  
4. 推荐库：**Ragas**（可与 LangChain / LlamaIndex 等集成）

### 5.2 核心指标（Ragas 视角）

| 指标 | 英文 | 看什么 | 差了多半改 |
|------|------|--------|------------|
| 忠实度 | **Faithfulness** | 答案能否从上下文推出 | 生成/Prompt/压缩；或上下文本身错 |
| 答案相关性 | **Answer Relevance** | 答是否对准问题 | Prompt；或检索跑题 |
| 上下文精度 | **Context Precision** | 相关块是否排在前面 | 重排、融合、过滤 |
| 上下文召回 | **Context Recall** | 真相应有的依据是否被召回 | 切片、混合检索、Query 改写/扩展 |
| 上下文实体召回 | **Context Entities Recall** | 关键实体是否出现在上下文 | 术语库、切片、图谱类手段 |
| 答案正确度 | **Answer Correctness** | 与标准答案的语义+事实一致 | 端到端，先分检索/生成定位 |

### 5.3 另一套常用三分法（产品打分）

| 缩写 | 含义 | 用途 |
|------|------|------|
| **CR** | Context Relevancy 检索相关性 | 检回的是否与问题相关 |
| **AR** | Answer Relevancy 答案相关性 | 是否回答了问题 |
| **F** | Faithfulness 可信度 | 有无幻觉 |

粗分：完美 1.0 / 可接受 0.75 / 缺失 0.5 / 错误 0。

### 5.4 最小评测作业（今天可设计、本周可跑）

- [ ] 20～50 条：`问题 | 标准要点 | 来源文档`  
- [ ] 每次改动只改一个环节  
- [ ] 记录：Context Recall / Precision / Faithfulness / 人工可接受率  
- [ ] 线上保留 👍👎 与差评 case 回流

## 6. 优化菜单（按症状查）

### 6.1 总原则

**尽量把模糊检索变成精确检索**（元数据、模块标签、关键词、结构化字段）。  
顺序默认：

```
评测定位 → 解析/清洗 → 切片 → Embedding/库 → 混合检索
         → Query 侧 → Rerank/压缩 → Prompt/溯源
         →（仍不够）子查询/Agent →（关系型）Graph
         → 慢贵再动缓存/量化/路由
```

### 6.2 症状 → 手段

| 症状 | 先试（成本低→高） | 资料关键词 |
|------|-------------------|------------|
| **解析乱 / 表碎 / OCR 错** | 清洗模板噪声；版面分析；跨页表合并；OCR+LLM 纠错 | 文档解析、OCR、预处理流水线 |
| **切片割裂、答案缺半句** | 语义切；加 Overlap；调 chunk 大小；句子窗口 | 滑动窗口、动态重叠 |
| **术语对不上** | 领域词库/同义归一；元数据标签 | 术语词库 |
| **漏召回** | 混合检索；Query 重写/扩展；HyDE；增大 K 再重排 | BM25、HyDE、多路召回 |
| **召回杂、噪声大** | 元数据过滤；Rerank；动态阈值；提示压缩 | 重排序、自查询 |
| **专有名词/编号搜不到** | 加强 BM25/关键词；精确字段；少靠纯向量 | 混合检索 |
| **答案幻觉、无依据** | 强制「仅依据上下文」；溯源；事实验证；降温度 | 幻觉、Faithfulness |
| **长答案结构乱** | 分段生成；提纲再写；记忆/状态 | 分段生成 |
| **多跳 / 跨文档推理差** | 子查询；多轮检索；Modular/Agentic | 任务分解、Agentic |
| **要查库表** | Text2SQL + Schema 约束 + 黄金 SQL | Text2SQL |
| **图文混排** | 先 OCR 进文本索引；再跨模态 embedding | 多模态、联合索引 |
| **慢** | 缓存热点；ANN/量化；减上下文；轻量 rerank | vLLM、缓存 |
| **贵** | 冷热模型；路由；压缩上下文；小模型重排 | 冷热分层 |
| **黑盒难调** | Tracing + 固定评测集回归 | LangSmith |
| **要执行动作** | Tool/MCP + HITL；慎全自动 | MCP、RPA、HITL |

### 6.3 Advanced 三刀（检索前/中/后）

| 阶段 | 常用手段 |
|------|----------|
| **检索前** | 更好解析与分层索引、元数据、Query 重写/扩展、HyDE、自查询 |
| **检索中** | 混合检索、多路融合、HNSW/参数、阈值 |
| **检索后** | Rerank、压缩、校验与溯源、再生成 |
